Open Routing validates a form submission, resolves company enrichment and CRM
ownership, and selects a destination using routing rules and territories.
Each decision includes the provider facts and rule trace that explain the result.

The SDK is under active development. Start with the contact-sales example in this
repository to explore its contracts and behavior.

## From submission to destination

1. Parse the submitted fields against a typed schema.
2. Resolve normalized enrichment and CRM ownership through providers.
3. Evaluate routing rules, ownership, and territories.
4. Return an explainable decision to the host application.
5. Let the host record the result and redirect the visitor.

The core package contains no HTTP server, UI, vendor credentials, or example data.
The contact-sales example supplies these application boundaries using deterministic
fixtures so you can try it without a CRM account.

See [submission and decision records](/decision-records) for the persistence
lifecycle and privacy behavior.
